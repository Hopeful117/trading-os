# ADR-022 — Stratégie de cache et de fraîcheur de Market Intelligence

* **Statut** : En discussion
* **Date** : 2026-07-29
* **Décideurs** : Équipe Trading OS
* **Périmètre** : Market Intelligence et services fournisseurs de contexte
* **Complète** : ADR-020, ADR-021

## 1. Contexte

Market Intelligence construit des analyses à partir de nombreuses sources :

* données de marché ;
* historique ;
* carnet d’ordres ;
* transactions récentes ;
* résultats déterministes ;
* actualités ;
* calendrier économique ;
* données de compte ;
* positions ;
* règles de risque ;
* observations précédentes ;
* résultats IA.

Une analyse active ou passive peut demander plusieurs fois des informations identiques ou proches dans une courte période.

Sans stratégie de cache, le système risque :

* de multiplier les appels interservices ;
* de recalculer inutilement des analyses déterministes ;
* de répéter des traitements IA coûteux ;
* d’augmenter les latences ;
* de créer une charge excessive ;
* de produire des résultats fondés sur des données incohérentes dans le temps.

Toutefois, une réutilisation excessive peut également être dangereuse.

Le marché évolue rapidement et les données n’ont pas toutes la même durée de validité. Un carnet d’ordres peut devenir obsolète en quelques instants, alors qu’une information macroéconomique peut rester pertinente pendant plusieurs heures.

La stratégie doit donc arbitrer entre :

```text
Réutilisation
Fraîcheur
Cohérence
Coût
Traçabilité
Isolation des données
```

---

## 2. Distinction fondamentale

ADR-022 distingue trois concepts.

### Cache technique

Une donnée temporaire, recalculable et supprimable sans conséquence métier.

Exemples :

* réponse Market Data récente ;
* contribution de contexte déjà construite ;
* résultat déterministe encore valide ;
* métadonnées techniques.

### Résultat d’exécution

Un résultat produit dans le cadre d’une `AnalysisExecution`.

Il appartient à l’historique technique de cette exécution et peut éventuellement être réutilisé lorsque les conditions sont compatibles.

### IntelligenceObservation

Une connaissance métier durable, validée et persistée.

Une observation n’est pas une entrée de cache.

Sa suppression ou sa modification possède une signification métier.

```text
Cache
    Temporaire
    Recalculable
    Non fiable comme mémoire métier

IntelligenceObservation
    Durable
    Traçable
    Porteuse de sens métier
```

---

## 3. Objectifs

ADR-022 doit définir :

* ce qui peut être mis en cache ;
* à quel niveau le cache appartient ;
* comment les clés sont construites ;
* comment la fraîcheur est représentée ;
* comment les entrées sont invalidées ;
* dans quelles conditions un résultat déterministe peut être réutilisé ;
* dans quelles conditions un résultat IA peut être réutilisé ;
* comment isoler les données par utilisateur ou périmètre ;
* comment le cache interagit avec l’idempotence ;
* comment éviter qu’une entrée obsolète soit silencieusement considérée comme actuelle.

---

## 4. Principes déjà proposés

Les principes suivants servent de point de départ.

### 4.1 Le service source reste propriétaire de ses données

Market Intelligence ne doit pas devenir une copie permanente des données des autres services.

Chaque service reste propriétaire :

* de la donnée primaire ;
* de sa rétention ;
* de sa politique de fraîcheur ;
* de son cache interne éventuel.

### 4.2 Le cache ne remplace pas la provenance

Toute donnée réutilisée doit conserver :

* sa source ;
* sa date de production ;
* sa date d’expiration ;
* sa version ;
* son périmètre ;
* sa classification.

### 4.3 La fraîcheur est spécifique au type de donnée

Il ne doit pas exister un TTL global unique pour tout `IntelligenceContext`.

Exemple conceptuel :

```text
Market metadata       durée relativement longue
Recent trades         durée courte
Order book snapshot   durée très courte
News article          durée plus longue
Risk state            dépend de l’activité du compte
AI interpretation     dépend du contexte complet
```

Les durées exactes devront être configurables et définies par type de donnée ou de capacité.

### 4.4 L’isolation est obligatoire

Une entrée contenant des données :

```text
USER_CONFIDENTIAL
TRADING_SENSITIVE
```

doit être isolée par utilisateur, compte, tenant ou périmètre de sécurité approprié.

Elle ne peut jamais être réutilisée pour un autre utilisateur.

### 4.5 Une entrée expirée n’est pas fraîche

Une entrée expirée ne doit pas être renvoyée silencieusement comme donnée actuelle.

Une éventuelle utilisation en mode dégradé doit être :

* explicitement autorisée ;
* signalée dans le résultat ;
* tracée ;
* interdite pour certains types de données critiques.

# 5. Première décision à trancher — Qui possède le cache ?

Plusieurs niveaux de cache sont envisageables.

## Option A — Cache uniquement dans les services sources

Chaque service met en cache ses propres données.

Exemples :

```text
Market Data Service
    cache des prix et métadonnées

News Service
    cache des articles et événements

Trading Core
    cache limité de certains états calculés
```

Market Intelligence ne conserve aucun cache applicatif de contexte.

### Avantages

* ownership très clair ;
* pas de duplication ;
* chaque service connaît la fraîcheur de ses données ;
* invalidation locale plus simple.

### Limites

* Market Intelligence doit reconstruire chaque contexte ;
* appels réseau répétés ;
* aucune réutilisation directe des contributions assemblées ;
* difficulté à réutiliser un résultat de capacité.

---

## Option B — Cache centralisé dans Market Intelligence

Market Intelligence met en cache :

* les contributions ;
* les contextes ;
* les résultats déterministes ;
* certains résultats IA.

### Avantages

* réduction importante des appels ;
* construction rapide des contextes ;
* vue centralisée de la fraîcheur ;
* réutilisation facilitée.

### Limites

* duplication de données ;
* risque de devenir propriétaire implicite des données ;
* invalidation complexe ;
* volume potentiellement important ;
* exposition accrue des données sensibles.

---

## Option C — Stratégie hybride

Les services sources restent propriétaires du cache des données primaires.

Market Intelligence peut conserver uniquement des caches dérivés et bornés :

* références vers des données sources ;
* contributions normalisées ;
* résultats déterministes ;
* résultats de capacités ;
* fragments de contexte ;
* métadonnées de fraîcheur.

Market Intelligence ne considère jamais ces caches comme la source de vérité.

### Avantages

* ownership préservé ;
* réduction des appels et recalculs ;
* cache adapté au domaine de l’orchestration ;
* possibilité de réutiliser des résultats coûteux ;
* meilleure maîtrise de la fraîcheur.

### Limites

* deux niveaux de cache à coordonner ;
* clés et invalidation plus complexes ;
* besoin d’une provenance rigoureuse ;
* risque de duplication partielle.

---

## 6. Proposition initiale

La stratégie hybride semble la plus cohérente avec l’architecture actuelle.

Elle pourrait être formulée ainsi :

> Les services producteurs restent propriétaires des données primaires et de leur cache local. Market Intelligence peut mettre en cache des représentations dérivées, des contributions normalisées et des résultats de capacités lorsque ceux-ci sont recalculables, bornés dans le temps, isolés selon leur périmètre de sécurité et accompagnés de métadonnées de provenance et de fraîcheur. Une entrée de cache de Market Intelligence ne devient jamais une source de vérité métier.

Cette décision permettrait d’introduire une hiérarchie logique :

```text
Source of truth
    Service producteur

Cache de données primaires
    Service producteur

Cache de contributions et résultats dérivés
    Market Intelligence

Mémoire métier
    IntelligenceObservation
```

## 7. Question ouverte n°1

**Validons-nous la stratégie hybride comme règle d’ownership du cache ?**

En cas de validation, les prochaines décisions d’ADR-022 porteront sur :

1. les catégories exactes de données pouvant être mises en cache ;
2. la structure des clés ;
3. la fraîcheur et les TTL ;
4. l’invalidation ;
5. la réutilisation des résultats IA ;
6. l’interaction entre cache, idempotence et `AnalysisExecution`.
