# ADR-037 — Persisted Strategy Definitions as Runtime Source of Truth

## Status

Accepted

## Date

2026-08-22

## Context

ADR-036 split strategy governance into two explicit dimensions
(`ValidationStatus` + `StrategyOperationalStatus`) with a single domain
predicate `StrategyDefinition.isEligibleForLiveEvaluation()`, and the pipeline
gates on it before applicability and evaluation.

Discovery for Story 0016 then revealed that this governance model had no
runtime effect:

* `StrategyDefinitionRepository` (port + JPA adapter + `strategy_definitions`
  schema V4/V7) existed but had **zero production consumers**;
* `ProductionIntelligencePipeline` loaded strategies exclusively via
  `BuiltinStrategies.all()`, recreating initial definitions on every run;
* any governance state persisted in the database would therefore have been
  ignored — promoting a strategy required a code change and redeployment;
* `recordValidation(...)` had no production caller.

Two sources of truth existed in potentia: code (builtin catalogue) and
database (persisted definitions). Only one was wired, and it was the wrong one
for runtime governance.

## Decision Question

How should builtin definitions, persisted definitions, and the live pipeline
relate so that governance is real, survives restarts, and preserves human
authority?

## Decision

### Responsibilities

```text
BuiltinStrategies
    software-owned catalogue: which strategies this software knows, and their
    INITIAL definitions (identity, semantics, applicability, parameters,
    initial governance)

strategy_definitions table
    persisted RUNTIME state of those strategies; source of truth for
    governance in this instance of Trading OS

ProductionIntelligencePipeline
    consumes ONLY persisted definitions
```

### Bootstrap policy

At application startup an idempotent bootstrap
(`BuiltinStrategyBootstrap`, Spring `ApplicationRunner`) seeds the catalogue:

* definition absent → inserted with its builtin initial state;
* definition present → LEFT UNTOUCHED. Persisted governance always wins;
  a restart must never reset governance to builtin initial values.
* Two consecutive bootstraps produce the same final state.

Identity is the existing domain identity `(StrategyId, version)`; no new
identity concept is introduced.

### Version policy

A new builtin version is a new persisted definition seeded with INITIAL
governance. Validation and activation are NEVER automatically inherited from
a previous version: new versions may change semantics, thresholds or inputs,
and therefore require their own validation (extends ADR-034 versioning
semantics).

### Restart invariant

Restarting the application never resets persisted governance to the builtin
initial state.

### Failure semantics

No silent fallback. If persistence fails at startup, bootstrap fails visibly;
if the pipeline cannot read persisted definitions, the run fails. The
in-memory catalogue is never used as a live substitute, because that would
recreate two competing sources of truth.

### Human authority

Bootstrap is seeding, not approval. It never constitutes implicit human
validation or activation of a strategy. Governance changes remain explicit
human decisions (mechanism to be provided by a future promotion story once
the validation-evidence semantics are decided).

## Consequences

Positive:

* STORY-0015 governance becomes operationally real: changing persisted state
  influences the next pipeline run without code changes.
* Strategy activation/deactivation becomes an operational concern decoupled
  from releases.
* Future scanners can consume the same persisted selection state.

Negative / accepted trade-offs:

* After rehydration, `scenario` falls back to the strategy name (existing
  convention since Story 0013: scenario remains deliberately unpersisted).
  Legacy opportunities created before this change carry scenario
  `OHLC_TREND`; newly created legacy matches use the rehydrated fallback.
  This is a bounded deployment-time display/dedup artifact, consciously
  accepted rather than reintroducing scenario persistence.
* An empty/unbootstrapped database yields zero strategies evaluated (visible,
  not silently substituted).

## Relation to Prior ADRs

* Extends ADR-034/036: governance dimensions unchanged; only their runtime
  materialization is now persistent.
* Preserves ADR-035 I-1/I-7/I-8 and strategy-agnostic orchestration; the
  pipeline still reasons exclusively in domain `StrategyDefinition`.
* Does NOT remove bootstrap-transition debt (`ShadowStrategyParityMonitor`,
  legacy conveniences) — unchanged scope.
* Does NOT define validation evidence semantics (separate future decision).

## Migration Required

NO. Schema V4/V7 already provides all required columns.
