# ADR-062 - Versioned Research Dataset Boundary

## Status

Proposed for Story 0108B.

## Decision

Market Intelligence owns a bounded, provider-neutral research dataset boundary.
The dataset layer combines immutable `FeatureSnapshot` facts produced under
`STRICT_OBSERVED` with explicitly selected immutable `ObservedMarketOutcome`
versions. It does not calculate either side of the pair.

V1 uses one sample per `FeatureSnapshot` and configured horizon. Outcome
selection is explicit by the complete outcome fingerprint identity established
by ADR-061; no latest-row or database-order selection is allowed. A population
specification is versioned and includes cutoffs, markets, projection/outcome
versions, horizons, accepted missingness and selected outcome fingerprints.

`ResearchSample` keeps features and objective outcomes separate. Numeric values
remain `BigDecimal`, categorical values remain strings, booleans remain boolean,
and feature missingness remains explicit. Objective outcomes are not labels and
no strategy or profitability interpretation is introduced.

The canonical V1 output is an immutable in-memory `DatasetManifest` plus
deterministically ordered JSON Lines export. The manifest fingerprint includes
the canonical population specification, exclusion diagnostics and ordered
sample fingerprints. The same inputs therefore produce the same dataset
fingerprint and serialized rows. Durable dataset tables are deferred until a
repository listing/materialization requirement exists; no mutable dataset
identity is introduced in V1.

## Invariants

- Future outcome evidence cannot enter feature snapshots or feature fingerprints.
- Pairing requires exact market, cutoff, horizon and version semantics.
- Missing values are never replaced with zero, false or a synthetic category.
- Corrections select a new outcome fingerprint and produce a new dataset
  fingerprint; existing facts are not mutated.
- Java owns factual deterministic research truth. Python owns later statistical
  preprocessing, splitting and model experimentation.

## Consequences

The boundary is reproducible and suitable for a future Python consumer without
introducing a research microservice, Python runtime, public endpoint, feature
store, warehouse or ML dependency. V1 population completeness is limited by
the persisted FeatureSnapshot population and explicitly selected outcomes;
exclusion counts preserve that limitation for later research.
