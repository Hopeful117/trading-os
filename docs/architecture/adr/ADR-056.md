## Context

Trading OS now has a canonical `IntelligenceContext` and existing deterministic
capabilities for quote spread, OHLC range, Market Structure and Trend Context.
The platform needs a small baseline that is independently useful, reproducible
and explainable before introducing ML or LLM interpretation.

ADR-049 already exists for reusable Market Structure ownership and is not
redefined by this decision. ADR-056 therefore defines the cross-family evidence
and analyzer boundary for Story 0106 without creating a second Market Structure
authority.

## Decision

Market Intelligence deterministic evidence is organized into four distinct
semantic layers:

```text
normalized facts
    -> deterministic features
    -> versioned deterministic analyses
    -> future statistical or semantic interpretation
```

Facts are direct normalized observations owned by their source service, such as
bid, ask, OHLC candles, event timestamps and article timestamps.

Deterministic features are mechanical transformations of facts, such as
midpoint, spread, basis points, return and range.

Deterministic analyses are typed, versioned rule results with explicit evidence,
such as `MarketStructureResult` and `TrendContextAssessment`.

Interpretations include probabilistic, semantic or recommendation claims such
as sentiment, opportunity quality, confidence, likely breakout and trade
recommendation. They are outside the deterministic baseline unless governed by
a separate explicit model decision.

## Analyzer Properties

Deterministic calculations SHALL preferably be pure, stateless, provider-neutral,
reproducible and testable. Mathematical calculation code SHALL NOT perform HTTP
calls, repository queries, provider acquisition, clock reads for evidence
eligibility, mutable global-state access, ML inference or LLM calls.

Acquisition and context assembly occur before calculation. The single
`IntelligenceContext.evaluationCutoff` is the evidence boundary. Operational
`computedAt` metadata does not expand that boundary.

The same accepted evidence, cutoff, algorithm version and configuration SHALL
produce the same material result.

## Typed Evidence

The authoritative deterministic representation SHALL remain typed domain
evidence. A generic `Map<String, Double>` or equivalent feature bag is not the
domain contract.

Existing artifact/execution compatibility may project typed calculations into
the established artifact representation where required. A future ML boundary
may explicitly project typed evidence into a versioned numeric `FeatureVector`:

```text
typed deterministic evidence
        -> versioned FeatureProjection
        -> versioned FeatureVector
        -> Python ML
```

The Java deterministic domain SHALL NOT be flattened merely for future ML
consumption.

## Story 0106 Baseline

The reduced baseline consists of:

1. Quote Quality / Spread: midpoint, absolute spread, relative spread and basis
   points when bid and ask are valid.
2. Bounded OHLC Temporal Measurements: range and simple return over an explicit
   ordered evidence window.
3. Existing Market Structure and Trend Context evidence, reused without a
   duplicate trend engine or generic trend score.

Spread regime labels, composite scores, order-flow analysis, absorption, news
sentiment, opportunities, TradePlans, Risk decisions and execution are not part
of this baseline.

## Temporal Integrity

One assembled `IntelligenceContext` has one canonical evaluation cutoff. Every
contributor and analyzer must respect it for candle occurrence/close time and
fetch/capture time where required.

Trend Context must use the request cutoff when supplied, rather than replacing
it with a current clock boundary. Market Structure derived through that path
must observe the same cutoff. Future evidence must not remain in the analytical
input in a way that changes result fingerprints.

## Missing, Stale and Invalid Evidence

Analysis results SHALL preserve explicit degraded semantics. The repository's
section statuses remain authoritative for context assembly. Typed deterministic
results may use equivalent statuses such as:

```text
AVAILABLE
INSUFFICIENT_DATA
STALE_INPUT
INVALID_INPUT
UNAVAILABLE
```

Missing, stale or invalid evidence must not be silently encoded as zero, false,
neutral or an unqualified NaN. An unavailable optional analyzer must not
invalidate unrelated valid analyzers.

For quote quality specifically, missing bid/ask is insufficient data, a
non-positive quote or `bid > ask` is invalid, and `bid == ask` is a valid zero
spread when temporal eligibility holds.

## Architecture and Authority

The existing capability, artifact and `AnalysisExecution` architecture remains
the composition boundary. Story 0106 does not introduce a parallel generic
analyzer framework or a new persistence model.

Narrow typed inputs are preferred for pure calculations. A spread calculation
does not depend on News, and an OHLC calculation does not depend on account or
Risk context. Existing `TrendContextAssessment` and `MarketStructureResult`
remain the authoritative typed deterministic results for their rules.

Deterministic Market Intelligence describes, measures and classifies under
explicit rules. It does not create `Opportunity`, `TradePlan`, Risk
authorization or execution authority. Trading Core and Risk remain authoritative
for account-specific financial authorization, and human authorization remains
required for execution.

## Persistence and Future ML/LLM

Story 0106 does not introduce a feature store, broad deterministic-result
persistence, labels, outcomes, ML, Python services, LLM integration, RAG or
embeddings. Existing artifact persistence and lineage remain in use.

Historical replay is only partial until source evidence can be reconstructed at
the same cutoff. A later Historical Feature / Context / Outcome Foundation
Story must establish replayable inputs and labels before ML begins.

Future LLM capabilities consume structured deterministic evidence as input and
do not recalculate its mathematics or override deterministic exclusions.

## Consequences

Positive consequences:

- Existing deterministic evidence has one explicit semantic boundary.
- Quote and OHLC calculations are reusable and independently testable.
- Existing Market Structure and Trend Context remain single authorities.
- Missing and invalid evidence remains inspectable.
- Future ML projection can be added without contaminating the Java domain.
- No analytical result becomes financial authorization by implication.

Trade-offs:

- Result status, version and evidence metadata must be preserved.
- Historical replay requires future source-retention work.
- Existing artifact projections may remain less richly typed for compatibility.
- Analyzer-specific completeness policies must be explicit rather than inferred
  from list size.

## Out of Scope

- Order-book context or history.
- Imbalance, liquidity depth, microprice, absorption or trade-tape analysis.
- RSI, MACD, Bollinger Bands, generic scores or new ATR semantics.
- News sentiment, Marketaux changes or semantic headline analysis.
- Opportunities, StrategyMatch changes, TradePlans, Risk or execution changes.
- ML, LLM, FeatureVector, labels, outcomes or feature-store infrastructure.
- Frontend changes and broad persistence redesign.
