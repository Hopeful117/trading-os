# ADR-069 - Checkpoint-Aware and Promoted Order Book Replay Acceleration

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-21 |
| **Related ADRs** | ADR-058, ADR-063, ADR-064, ADR-067, ADR-068 |
| **Related Stories** | Story 0141, Story 0142 |

---

## 1. Context

Story 0141 measured the remaining Research latency in the Market Data strict
Order Book replay path. The canonical evidence table contains approximately
`49.5 M` rows and the current repository path still scans and deserializes a
material number of deltas for each replay request.

Simple index alternatives were rejected because they either duplicate most of the
canonical evidence index or degrade sequence selection. The next candidates are
therefore derived replay accelerators: trusted checkpoints and/or immutable
promoted replay artifacts.

## 2. Decision Boundary

Market Data may introduce a derived replay accelerator only if all of the
following remain true:

- canonical normalized snapshots and deltas remain the authoritative evidence;
- strict replay still uses one valid sequence and `knownAt <= evaluationCutoff`;
- the accelerator retains independently verifiable source provenance;
- invalidated, ambiguous, incomplete, stale, or unknown state fails closed;
- invalidation and rebuild behavior are explicit and bounded;
- replay artifacts participate in ADR-067 dependency protection and retention;
- optimized output is semantically equivalent to canonical replay for identical
  authoritative inputs.

This ADR does not select checkpoints or promoted artifacts as the implementation.
Story 0142 must compare them using representative data and select the smallest
mechanism that satisfies the boundary with a material measured benefit.

## 3. Ownership

Market Data owns replay acceleration, sequence validity, evidence provenance,
promotion, invalidation, and rebuild behavior. Market Intelligence remains a
consumer of the provider-neutral replay contract and does not own replay state or
derived evidence.

## 4. Checkpoint Rules

If checkpoints are used:

- they are derived reconstruction anchors, never provider observations;
- each checkpoint identifies its sequence, source ordinal range, cutoff/known-at
  boundary, normalization version, and source evidence fingerprints;
- a checkpoint from an invalidated or ambiguous sequence is not replay-eligible;
- checkpoint creation is atomic with its provenance metadata and idempotent for
  the same source identity;
- a missing or unverifiable checkpoint falls back to canonical replay or an
  explicit unavailable/invalid result, never to stale state.

## 5. Promotion Rules

If promoted replay artifacts are used:

- promotion is allowed only for an available, trusted, complete replay;
- the artifact is immutable, content-addressed, and tied to a semantic replay
  identity;
- promotion records sequence identity, cutoff, source range, source fingerprints,
  provider provenance, normalization version, and trust status;
- promotion is atomic and idempotent;
- dependencies are protected until explicitly released under ADR-067;
- an artifact is not a substitute for the current operational book or an
  authorization to replay an invalidated sequence.

## 6. Freshness, Invalidation, and Rebuild

The accelerator must define:

- what event invalidates it;
- how sequence supersession and capture recovery affect it;
- how a partial or failed rebuild is represented;
- how stale or missing derived state is surfaced;
- how rebuild work is bounded, observable, resumable, and idempotent.

TTL alone is not a validity or release rule. Unknown dependency or provenance
state remains protected and fail-closed.

## 7. Rejected Shortcuts

- generic TTL-only replay cache;
- replacing canonical evidence with a materialized view without provenance;
- age-based artifact release;
- serving an artifact after sequence invalidation;
- silently mixing evidence from multiple sequences;
- changing the Market Intelligence contract to hide replay unavailability.

## 8. Consequences

Positive:

- replay latency can be reduced without duplicating canonical evidence semantics;
- repeated research replay can reuse independently verifiable derived state;
- invalidation and retention remain explicit and auditable.

Trade-offs:

- derived state introduces lifecycle and storage complexity;
- checkpoints and artifacts require rebuild and equivalence testing;
- retention cannot proceed while dependencies or provenance are unresolved.

## 9. Implementation Gate

Story 0142 must produce measured candidate comparisons and a concrete lifecycle
design before implementation. If the selected design materially changes ADR-067
contracts or ownership, this ADR must be updated and explicitly accepted before
source or schema changes proceed.
