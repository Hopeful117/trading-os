# ADR-066 - Canonical Versioned ResearchSample Binding and Experiment Feature Eligibility

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-19 |
| **Related ADRs** | ADR-060, ADR-061, ADR-062, ADR-064 |
| **Related Investigation** | FeatureSnapshot Completeness & ResearchSample Linkage Root-Cause Investigation |

---

## 1. Context

Research facts are immutable and versioned. Multiple `FeatureSnapshot` facts may
legitimately share the same market and evaluation cutoff because they can be
produced from different context evidence, capability plans, reprojections, or
projection versions. Multiple `ObservedMarketOutcome` facts may likewise share
the same market, cutoff, and horizon when objective evidence or the outcome
definition evolves.

Consequently, market plus cutoff is not a sufficient research identity, and
market plus cutoff plus horizon is not a sufficient outcome-version identity.

The existing dataset boundary explicitly selects outcome fingerprints but loads
all snapshots found in a cutoff range. A later immutable snapshot version can
therefore change a population that has not changed its specification.

Feature availability is also experiment-dependent. A schema-valid snapshot may
contain explicit `UNAVAILABLE`, `INSUFFICIENT_DATA`, `STALE_INPUT`,
`INVALID_INPUT`, `UNSUPPORTED`, or `NOT_APPLICABLE` values. Requiring every
`FeatureProjectionV1` value to be `PRESENT` is not valid for experiments such as
the directional Q1 control, which does not condition on feature values.

## 2. Decision

Every `ResearchSample` must bind exactly one immutable `FeatureSnapshot` and one
immutable `ObservedMarketOutcome` selected by their semantic identities.

The canonical research identity uses immutable fingerprints, not generated
database UUIDs alone:

```text
FeatureSnapshot:
    feature snapshot fingerprint

ObservedMarketOutcome:
    marketId + evaluationCutoff + horizon
    + outcomeDefinitionVersion + outcomeFingerprint
```

Database identifiers remain operational persistence identities and are not the
portable research identity.

`ResearchPopulationSpec` must explicitly select the FeatureSnapshot identity for
each population sample and must continue to explicitly select the outcome
fingerprint for each market, cutoff, and horizon. A population must not select a
snapshot implicitly by range query, row order, creation time, or a latest-version
rule.

An unresolved or conflicting selected identity fails closed. The system must not
substitute another snapshot or outcome at the same cutoff.

## 3. Experiment Feature Eligibility

Each research experiment declares its required feature names through a small
immutable feature-requirements value object.

Eligibility has two separate layers:

```text
schema validity:
    all FeatureProjectionV1 keys exist with valid typed representations

experiment requirements:
    every feature explicitly required by the experiment is PRESENT
    or satisfies that experiment's declared missingness policy
```

Missingness on non-required features does not exclude a sample. The existing
`acceptedFeatureMissingness` population field remains available for compatibility
with current dataset policies, but required-feature checks are the authoritative
experiment-specific eligibility rule.

The Q1 directional control declares zero required domain features while still
requiring a schema-valid immutable FeatureSnapshot and an exact immutable
outcome. It does not encode Order Book, fee, funding, or economic execution
requirements as FeatureProjection features.

## 4. Population Reproducibility

A frozen population is defined by its explicit immutable snapshot and outcome
selections plus its population, dataset, projection, outcome, horizon, and
feature-requirement versions.

Persisting a new snapshot or outcome version must not change an existing
population or dataset fingerprint. A population that references a missing fact
is invalid and cannot be rebuilt by selecting a replacement.

Dataset manifests record the selected semantic identities and experiment feature
requirements without duplicating complete artifact payloads.

## 5. Temporal Integrity

`FeatureSnapshot` remains a projection of deterministic evidence known at its
evaluation cutoff. Future outcome evidence must not enter its payload or
fingerprint.

`ObservedMarketOutcome` remains an immutable objective future-market fact. It
does not contain strategy direction, execution, commission, funding, P&L, risk,
or trade-plan semantics.

This decision does not permit mutation or backfill of historical snapshots or
outcomes. A future reprojection, if introduced, creates a new immutable,
versioned fact with explicit provenance.

## 6. Consequences

- Duplicate cutoff versions are safe when explicitly selected.
- Missing selected facts fail closed instead of silently changing research truth.
- Dataset exports are stable after new immutable artifacts are persisted.
- Q1 can use legitimate historical snapshots with non-required unavailable values.
- Feature-conditioned experiments must declare their required feature names.
- `feature-projection-v1` remains unchanged.
- Historical evidence, fees, funding, Order Book replay, and economic execution
  semantics remain outside this decision.
