# ADR-058 - Historical Market Intelligence Replay and Evidence Acquisition Boundary

## Status

Accepted for Story 0107B implementation.

## Related ADRs

- ADR-035 - Strategy Evaluation Live and Backtest Compatibility
- ADR-048 - Intelligence Evidence and Authority
- ADR-049 - Reusable Deterministic Market Structure Capability
- ADR-056 - Deterministic Market Intelligence Evidence and Analyzer Boundary
- ADR-057 - Historical Market Evidence, Known-At Semantics, and Source Retention

## Decision

Market Intelligence uses one `IntelligenceContext` domain and one deterministic
analysis layer for live and strict historical analysis. The acquisition boundary
is selected by an explicit `EvidenceAcquisitionPolicy`, independently of
`AnalysisExecutionMode`.

The implemented policies are:

- `LIVE_CURRENT`: use the existing provider-backed Market Data path;
- `STRICT_OBSERVED`: consume only Market Data durable `CAPTURED` evidence
  eligible at the request's explicit `evaluationCutoff`.

Strict replay never falls back to a current provider response. Market Data owns
historical facts and strict selection. Market Intelligence validates the wire
contract, assembles context, and runs the existing deterministic capabilities.

All replay sections use one canonical cutoff. Partial contexts remain valid and
use the existing context statuses and quality model. Historical OHLC, Market
Structure, and Trend Context are the first replay slice. Historical snapshots,
quotes, News, economic-event revisions, outcomes, backtesting, and ML remain
outside this decision.

Historical evidence identity participates in section provenance and context
fingerprinting through a bounded aggregate fingerprint. Execution persistence
retains the cutoff and evidence policy so asynchronous redispatch cannot change
the temporal meaning of an execution.

Service-to-service invocation uses `POST /internal/v1/intelligence/analyses`.
The endpoint accepts only the authenticated `trading-core` service identity,
requires an idempotency key, and is not exposed through the public Gateway or
frontend surface. It returns `202 Accepted` with the created execution identity.

## Consequences

Live acquisition remains unchanged. Strict historical replay can be tested with
the provider unavailable and uses the same deterministic analyzers and profiles
as live analysis. A historical execution may be partial when non-replayable
sections are unavailable. Future extensions for quotes or News must introduce
their own provider-neutral strict source contracts rather than weakening this
policy.
