### Implementation behavior

`HistDataOfflinePipeline.read` groups parsed M1 records by timestamp. Exact
duplicates retain one record; conflicting duplicates quarantine every record at
that timestamp and add quality events. A source chronology inversion records
both involved timestamps in `chronologyAnomalyTimestamps`.

`qualityEvidence` propagates both the quarantine and chronology flags to the
containing H1 bucket. `Ml01H1AdmissibilityEvaluator` rejects a bucket carrying
either flag. The affected H1 buckets therefore do not enter the exploratory
candidate list used by `Ml01HistDataPreparation`.

All anomaly buckets were absent from the admissible candidate sequence. The

continuity rejection behavior. The dependency index sets for every eligible row
were then checked against the anomaly bucket indexes.

## 6. Origin Of `BLOCKED_BY_DATA_INTEGRITY`

The readiness status is a source-wide rule, not an eligible-row contamination
rule:

```java
if (rows.isEmpty() || imports.stream()
        .anyMatch(value -> value.conflictingDuplicateRows() > 0)) {
    return "BLOCKED_BY_DATA_INTEGRITY";
}
```

The same import-level condition also makes `pipelineValidated` false. It is
evaluated before considering whether quarantined source buckets occur in a
published eligible row or dependency window.

Therefore the blocker is a combination of:

1. a source-wide integrity policy intentionally triggered by any conflicting
   duplicate rows; and
2. observation-level admissibility that excludes the affected H1 buckets.

The current evidence does not support downgrading the source-wide rule. A human
scientific/governance decision would be required to distinguish a globally
blocked source from a separately published, clean eligible subpopulation.

The chronology inversions reinforce the affected-bucket exclusion but are not
the direct condition that emits `BLOCKED_BY_DATA_INTEGRITY`; the conflicting
duplicate count is.

## 7. Partition Implementation Assessment

`PartitionConfiguration` requires all four values together:

- `trainEndExclusive`;
- `validationEndExclusive`;
- `testEndExclusive`;
- `embargo`.

`requiresApproval()` sets all four to `null`, and the existing bundle used that
configuration. With a complete configuration, the implementation:

- assigns rows using common chronological boundaries;
- marks rows outside the final boundary as `OUT_OF_RANGE`;
- excludes TRAIN rows whose latest available future outcome crosses the train
  boundary;
- excludes VALIDATION rows whose latest future outcome crosses the validation
  boundary;
- applies embargo after train and validation boundaries;
- permits ordinary within-partition rolling overlap and reports it as
  statistical dependence;
- does not assign rows or calculate effective samples when parameters are
  unapproved.

The implementation does not expose a scaling-fit scope and does not explicitly
purge feature lookback overlap from a preceding partition. Its implemented
purge protects future outcomes at train and validation boundaries.

|---|---:|---:|---:|---:|

The disjoint count is a conservative greedy chronological lower bound, not a

significance estimate is inferred.

## 10. Assumed-Session Stratum

GBP/USD contains 50 rows in `ASSUMED_SESSION_TRANSITION`; EUR/USD contains none.
All 50 GBP/USD rows have exactly one assumed feature transition and an
`INSUFFICIENT_DATA` feature projection:

| Diagnostic | Count |
|---|---:|
| Assumed rows | 50 |
| Feature status `INSUFFICIENT_DATA` | 50 |
| Feature reason `Historical OHLC contains a temporal gap` | 50 |
| Exclusion `FEATURE_NOT_PRESENT` | 50 |
| Feature observation count | 33 for the inspected rows |
| H+4 outcomes available diagnostically | 42 |
| H+12 outcomes available diagnostically | 26 |
| H+24 outcomes available diagnostically | 2 |
| Jointly eligible rows | 0 |

The cause is not primarily insufficient row count or the maximum-transition
limit. `VolatilityCalculator` rejects temporal gaps unless verified closure gaps
are explicitly allowed. The exploratory weekend transition is not verified
closure evidence, so the 33-candle history remains temporally discontinuous and
the feature projection fails closed. This is consistent with ADR-095 and should
remain excluded from the first ML-01.2 exploratory population unless a human
scientific decision changes the protocol.

One metadata nuance is preserved: rows whose H1 quality is full observed can
carry `STRICT_OBSERVED` in feature provenance while still returning
`INSUFFICIENT_DATA` because the temporal continuity check rejects the assumed
gap. This does not convert the assumption into strict closure evidence.

## 11. Scientific Limitations And Human Decisions

- The source remains globally blocked by the existing conflicting-duplicate
  policy even though no eligible dependency intersects an anomaly bucket.
- The analysis establishes no identified impact, not global source cleanliness.
- Train/validation/test boundaries, embargo, purge policy for feature lookback,
  scaling-fit scope and minimum effective samples require explicit approval.
- Rolling-window dependence is substantial; raw counts must not be treated as
  independent samples.
- The assumed-session stratum has no eligible feature rows and should remain
  excluded pending scientific approval.
- A separate decision is required on whether a clean eligible subpopulation may
  be presented despite a source-wide integrity blocker.

## 12. Classifications

### Integrity impact

**`INTEGRITY_IMPACT_RESOLVED`**

All 16 conflicting source records and four chronology inversion events were
located with line numbers and H1 buckets. The dependency footprint for all 352 eligible rows was reconstructed from the
published provenance and showed zero direct, feature or outcome intersections;
zero rows have unknown contamination status. This does not authorize changing
the source-wide integrity rule.

### Partition feasibility

**`STRUCTURALLY_FEASIBLE`**

The existing implementation can assign common chronological boundaries, purge
future-window crossings and apply embargo. Diagnostic scenarios retain rows in
all main strata only when the time placement permits it. Scientific feasibility
remains conditional on human approval of boundaries, feature-overlap policy,
scaling scope, embargo and minimum effective samples.
