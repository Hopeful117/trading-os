# ML-01.1 - Dukascopy Prepared Dataset Scientific Validation

## 1. Executive Summary

The complete normalized 12-month Dukascopy BID M1 dataset was validated and
prepared through the Java-owned Dukascopy pipeline for EUR/USD and GBP/USD.
No interpolation, synthetic candles, session assumptions, clustering, scaling,
or model fitting was performed.

The primary 55/60 profile produced technically available joint feature/outcome
anchors:

| Instrument | Joint available | Joint scientifically eligible |
|---|---:|---:|
| EUR/USD | 2,145 | 0 |
| GBP/USD | 1,630 | 0 |

`jointEligible` remains false because chronological partition, purge, embargo
and minimum effective-sample parameters have not received separate scientific
approval.

The dataset is technically ready for scientific review, but it is not approved
for ML-01.2. Remaining blockers are scientific approval and effective-sample
validation, not source acquisition integrity.

## 3. Hardening Results

### H1 aggregation performance

The original aggregation repeatedly scanned all M1 observations for every H1
bucket and also repeatedly scanned event sets. The implementation now groups
M1 observations and integrity events by UTC hour once, preserving ordering,
missing-minute evidence, duplicate counts, overlap detection and fail-closed
classification.

The unoptimized implementation exceeded the local 120-second execution limit
before completing the first full instrument/profile run. The optimized
implementation completed each instrument/profile in approximately 81-111
seconds and completed all six bundles in approximately 9.5 minutes. A strict
before/after benchmark on identical isolated JVM conditions was not available;
the former timeout and latter completed timings are reported as observations,
not as a controlled speedup claim.

### Outcome fingerprints

The previous outcome fingerprint omitted intermediate future closes. It now
includes the outcome definition version, horizon, reference cutoff and price,
every future H1 timestamp, close and source fingerprint. A regression test uses
two trajectories with identical starting and ending prices and verifies that
realized volatility, directional efficiency and fingerprints differ.

### ADR-096 consistency

ADR-096 now distinguishes:

1. Accepted human policy: recorded.
2. Deterministic implementation authorization: recorded through Story 0229.
3. Bounded research-bundle generation: authorized for this validation.
4. Partition, purge, embargo and effective-sample scientific approval: absent.
5. ML-01.2/KMeans authorization: absent and out of scope.

## 10. Scientific Limitations and Gates

- The source is technically valid and reproducible at the acquisition boundary.
- Partial H1 candles materially dominate the technically available feature
  windows, so measurement sensitivity remains material.
- Strict 60/60 joint availability is zero for both instruments.
- Chronological feasibility is diagnostic only and does not approve any split.
- Purge and embargo values used here are candidate diagnostics, not approved
  scientific parameters.
- No minimum effective-sample threshold has been approved.
- `jointEligible` is zero by design.
- KMeans, clustering, scaling, model fitting and ML-01.2 were not executed.

## 11. Recommendation

Treat the bundles as technically prepared evidence for human scientific review.
Do not start ML-01.2. The next decision must explicitly approve or reject the
55/60 exploratory population and separately define chronological partition,
purge, embargo and effective-sample requirements. If approved, rerun the final
post-fix real-data reproducibility comparison before any modeling workflow.
