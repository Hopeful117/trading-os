## Continuation: 2026-11-12 MCP Process Version Diagnosis

The filtered discovery blocker is now explained. The active bridge process started at `2026-11-10 01:56:18`, before commit `b8b90c1f` at `2026-11-10 23:07:05`. That commit added the `instrument` parameter and query forwarding to `list_markets`.

The active bridge therefore loaded the previous handler:

```text
list_markets() -> GET /api/v1/markets
```

It did not load the current handler:

```text
list_markets(instrument) -> GET /api/v1/markets?instrument=...
```

This explains why both filtered MCP calls failed while equivalent direct filtered Market Data requests succeeded: the running bridge sent the unfiltered approximately 1 MB catalog, which exceeded the MCP client's 262,144-byte limit.

No bridge restart was performed. No research scope or grant was inspected after this diagnosis, and no research execution was submitted.
